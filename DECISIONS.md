# Decisions

Choices made while working through the roadmap without asking. Newest last.

- **Jewels in the data.** RePoE puts jewel bases and jewel mods in the `misc` domain. `build_data.py` now keeps `misc` bases of class Jewel and their `misc` mods; bases carry `dom` and the pool only uses mods of the same domain. Cluster and abyss jewels stay out (different crafting rules).
- **Royale bases** (`...Royale...` ids) are dropped like Royale mods; they duplicated real base names such as Opal Ring.
- **Fuzzy base matching only for magic items.** Rare and normal items print the exact base name; only magic names wrap the base in affix names. Matching is on whole words, longest base name first.
- **Aura mods.** RePoE's text for mods like "Nearby Enemies have -9% to Fire Resistance" has a second line repeating the effect, which the game doesn't show. `compileTemplate` drops a line that is the tail of the previous line.
- **No git remote** is configured in this checkout, so work is committed on branch `claude/roadmap` but can't be pushed.
- **Summed Ctrl+C lines** are only split when no single mod can explain the value. When one mod fits (for example +180 life on a body armour), the parser picks the single mod even though a hybrid + smaller life mod could also produce it; Ctrl+Alt+C resolves that ambiguity and the UI suggests it.
- **"Exact" means numerically exact.** Reroll odds come from a one-dimensional integral on a log-time grid (step 0.04, about 1e-7 relative error against brute force). That is far below any other uncertainty, and the result is the same every run.
- **Exact-method fallbacks.** The exact engine needs every mod to belong to one group, every group to sit on one side, and every target to be met by mods of a single group. Otherwise it returns null and the planner simulates. This happens today only for one jewel group that has both prefix and suffix mods.
- **Shared constants.** The mod-count and alteration assumptions moved to `engine/assumptions.js` so the simulator and the exact engine use the same values.
- **Lock + Chaos instead of lock + Scour.** After a Scour with a side locked you would still need Exalts to add the other side, and the exalt-slam stage is already modelled by the alteration route. So the side-lock method uses Chaos Orbs, which keep the locked side and reroll the rest. Each try needs a new lock craft, because the Chaos Orb removes it (it's on the other side).
- **Kept mods under a lock.** The plan assumes the locked side is full, apart from slots kept for bench crafts on that side. This is conservative: fewer new mods on the open side.
- **Multimod plans are extra entries.** When two or more wanted mods can be bench crafted, the planner also runs the methods with two crafts plus multimod and keeps the best 4 of them, marked "+ multimod". Without prices the multimod version always has better odds, so ranking by cost (Phase 3) is what decides between them.
- **"Cannot roll Attack/Caster Modifiers"** is offered for the exalt stage of the alteration route when none of the remaining wanted mods carry the tag, and only when it improves the odds. It is crafted right after the Regal if a slot is free, and removed before the final bench crafts.
- **Harvest data without a reachable source.** The build environment can reach only GitHub, so the PoE Wiki couldn't be checked. `harvest.json` lists the 12 tag reforges and the two keep-side reforges, which have been stable since 3.17. Lifeforce costs are `null` rather than guessed, and the "more common" multiplier (10, like a fossil's "more") is a documented assumption. Every Harvest plan is labelled approximate.
- **Manual data is loaded at runtime** (`loadDb` fetches `poe1.json` plus `manual/*.json`) instead of being merged by `build_data.py`. That way the hand-written files can be fixed without a RePoE checkout.
- **Annul policy.** "Annul every miss forever" turns into a random walk once the item is full: it's slow and very expensive. The comparison uses the policy players actually follow: annul a miss up to K times (1, 2 or 3), then start over. It's simulated (4,000 runs per K), because the annul loops make the exact state space too large for the browser.
- **Influenced exalts on a fresh roll.** An influenced Exalted Orb only works on an item without influence. The plan rolls the other wanted mods first, on a base without influence, then slams; a miss means starting over. Odds assume both sides have room, because the stage-1 item's free slots aren't tracked. That's conservative.
- **Awakener scope.** Planned only when exactly one wanted mod comes from each of the two influences. Each input item gets that mod from one influenced Exalted Orb, so it's the only influenced mod and is surely kept. The rest of the wanted mods come from the awakened roll, and the steps mention finishing with exalts or the bench instead.
- **Eldritch rank** is the number at the end of the implicit's mod id (1 = Lesser … 6 = Perfect). Dominance means a strictly higher rank, or the only eldritch implicit. "Presence" variants count by their id number.
- **Eldritch Annulment isn't planned on its own.** In these plans it would only replace a side lock + annul, and the annul policy (item 3) already covers annulling misses. The orb is named in the data file for later.
- **Unveil options** are modelled as 3 draws by weight without repeating a mod group, from the unveiled mods of the veiled mod's side. Mods already on the item don't change the options, except that the wanted mod's own group must be empty (enforced in the roll through `absentGroups`).
- **Aisling** is only planned without bench crafts, and assumes the stage-1 item is full (6 mods). That fixes the veiled mod's side to the side of the removed mod.
- **League mechanic left empty.** I couldn't check the 3.29 Allflame crafting rules (no access to the patch notes or the wiki from this environment), and inventing them would give wrong advice. So `league.json` has the hook and an empty list, and the page states the mechanic isn't modelled. Adding the 3.30 mechanic means adding entries with a source; no code changes are needed for the supported craft types.
